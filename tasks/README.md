# 开发任务导航

每次将当前TASK完整交给Coding Agent，并让它按AGENTS.md读取相关契约。TASK是实施边界，不是第二套数据库规范。

| TASK | 名称 | 前置 | 完成标志 |
| --- | --- | --- | --- |
| 001 | 工程现状核对与基础初始化 | 无 | 可复现构建、实际命令与依赖清单 |
| 002 | 数据库与API公共基础 | 001 | 26表、真实MySQL约束和公共组件测试 |
| 003 | Agent、数据集、方案版本管理 | 002 | 草稿编辑、发布不可变、前后端联调 |
| 004 | 在线Mock执行与Worker基础 | 003 | Run领取、租约、重试、封口、待评测Job |
| 005 | 规范JSONL离线导入 | 004 | 逐行回执、幂等与恢复，统一Run/Job |
| 006 | Trace检索与可视化 | 005 | 尝试隔离、游标、证据跳转 |
| 007 | 统一规则评测引擎 | 006 | JobAttempt与最终Result、聚合正确 |
| 008 | Judge与真实Runner适配 | 007 | 可选真实调用、固定配置与可审计证据 |
| 009 | 人工标注与失败归因 | 007；展示联调建议008后 | 乐观锁与追加历史 |
| 010 | 实验报告与回归 | 008,009 | 指标分母、配对、门禁与缺失处理 |
| 011 | Outbox/RabbitMQ可靠性增强 | 010 | 故障恢复与至少一次投递验证 |
| 012 | 压测与有证据的优化 | 011 | 基线、瓶颈、对照与限制 |

TASK-011并非首次实现可靠性；TASK-004/007必须已有数据库领取、租约、幂等和超时回收，011只增加消息通知与系统故障演练。若调整顺序，先检查实际依赖而非直接按编号并行。

## 通用交付格式

1. 当前分支、Git Commit ID（若仓库允许并已完成本地提交）；未提交时说明原因。
2. 新增/修改文件与行为，说明当前TASK边界。
3. 数据库、API、事件契约变化及其文档位置。
4. 实际执行命令、退出码、通过/失败/跳过数量。
5. 未执行检查及环境原因，不以推测代替通过。
6. 已知问题、设计差异和下一TASK前置是否满足。

用户授权开发TASK时可按交付要求提交本地Git commit，禁止擅自push、生产部署或发送外部消息。任务完成停止，等待验收。
